# v0.2.0 Accounts and profiles (draft)

Draft release notes. Status: **on the development site, not in production**. `release/0.2.0` reached `develop` on
October 19, 2026 (#88). A batch of fixes from `release/0.3.0` followed on October 20 (see "Also in this release"),
by owner decision, so production gets them in the same window. Production only in an approved release window (the
first is October 30, 2026). See [the development workflow](../development-workflow.md).

GitHub's generated notes (the PR list) are added automatically when the version is tagged; this page is the
human summary.

## What's new for families

- **Sign-up and household setup.** Create an account, confirm your email, then set up the family in four steps:
  the family, how many children, their first names, and inviting the co-parent (#41, #59).
- **Co-parent invitations.** Invite, resend or cancel from Settings until they join. Accepting joins the existing
  family (families are never merged), and expired, used or cancelled links get one clear screen (#41, #59).
- **Children approved by both parents.** A child added by one parent shows "Waiting for approval" until the other
  agrees; a rejected child is never created (#43).
- **Profile picker and child PINs.** A household device shows the family's profiles. Children sign in with a PIN
  and only reach child-safe pages. Three wrong PINs lock the profile and email both parents until a parent unlocks
  it (#44, #70).
- **PIN changes need the co-parent.** A new PIN waits for the other parent's approval in the inbox; the old PIN
  works until then (#46, #70).
- **A child's own tablet.** Pair it with a one-time code; it shows only that child (#45, #70).
- **Approvals history.** Decisions show their history and comments; unanswered requests expire after 14 days
  (#52, #54).

## Fixes

- A household device's profile picker shows only the parent who registered it (#58).

## Not visible yet

Milestone 3 calendar work (events, proposals, overlap warnings) is in this release's code but not reachable in the
app: the calendar page shows an honest empty state and Quick Add is disabled. The calendar API stays on for
signed-in, family-scoped use (owner decision, October 19, 2026). It ships for real in v0.3.0.

## Development site only

- **Invite-only sign-up**: `Identity:SignUp:InviteOnly` with `AllowedEmails` lets only listed testers register.
  Off by default, so production sign-up stays open (#71, #76).

## Also in this release (from `release/0.3.0`, October 20, 2026)

- **Branded emails.** Every email (confirm your email, reset your password, invitations for new and existing users,
  child safety notices) uses one HTML template with the approved logo, a plain-text version and dark mode (#106).
  Mail is sent through Brevo from `no-reply@parenthesisfamily.com`.
- **Staying signed in across restarts.** The data-protection key ring is stored in PostgreSQL, so a restart or a
  new deployment no longer breaks sign-ins or forms ("Invalid or missing antiforgery token") (#108).
- **Signup, invitations and profile picker design record.** The Request #1 board and the owner's decisions on its
  differences and gaps (#40).

## Database changes

Ten new migrations, applied automatically on deployment: invitations, child profiles, devices and child PINs,
device pairing codes, pending child PINs, approvals, decision comments, calendar, pending event changes, and the
data-protection key ring (its own `data_protection` schema, #108).
